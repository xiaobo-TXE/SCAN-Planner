# 轨迹与滑动地图回放手册（A2）

> **这份文档只解决一件事**：录一次最少的数据，回放时能一眼看清
> **机器狗从起点到拐角的 —— 全局轨迹 / 局部轨迹 / 实时轨迹 / 滑动地图**。
>
> 全部命令都在**真机的终端**里执行（NoMachine 里开终端即可，不用 ssh）。
> 脚本在 `~/record_tools/`；收纳全部数据的"全量录制"见另一份《真机录制与分析手册.md》。

---

## 0. 一句话版本

```bash
# 录（走到拐角，120s 自动停）
source ~/record_tools/env.sh
bash ~/record_tools/record_run.sh corner --tracks

# 放（两个终端）
ros2 bag play ~/bags/corner_<时间戳> &
ros2 launch scan_planner rviz.launch.py config:=replay
```

然后在 RViz 里 `Add → By topic → /lio/path → Path`，实时轨迹就出来了。其余四样配置里已经配好。

---

## 1. 每个新终端先做这一步

```bash
source ~/record_tools/env.sh
```

它会打印 `[env] 已就绪 ...`，等价于 source 了 `/opt/ros/humble` + `~/nav_ws` + `~/scan_planner_github_ws`。
**录包终端也必须 source 局部工作空间**，否则 `scan_planner_msgs` 缺、`/planning/bspline` 会被静默丢掉。

回放用的 `config:=replay` 来自代码分支 **`chore/record-tools`**（`rviz.launch.py` 支持 `config:=default|replay`）。

---

## 2. 录前自检（10 秒，建议每次都跑）

```bash
bash ~/record_tools/record_run.sh --check
```

正常应该看到：

| 检查项 | 期望 |
|---|---|
| 清单话题 | 除 `/test_event` 外都在（它只在打标注时才发） |
| `/loc/status` | `state: 3`（正在跟踪） |
| `/loc/robo/odom` | ≈ 10 Hz |
| `/cmd_vel` | ≈ 100 Hz |

有缺失就先别录，先查节点是否都起来了。

## 3. 录制：一条命令

```bash
bash ~/record_tools/record_run.sh corner --tracks
```

- `corner` 是标签，随便取；包会存到 `~/bags/corner_<时间戳>/`
- **默认 120 秒自动停**（原因见下面的带宽说明）；想手动停用 `--duration 0`
- 停止时脚本会等 rosbag 真正 finalize 完再归档，别重复按 Ctrl-C
- 想顺便标事件：`--auto-events`（自动标"卡住/恢复"），或另开终端
  `bash ~/record_tools/record_run.sh --event "拐角卡死"`

### 这个档录了什么

| 你要看的 | 话题 | 所属坐标系 | 备注 |
|---|---|---|---|
| **全局轨迹** | `/global_path` | **MAP** | 保留型（latched），只有一帧 |
| **局部轨迹** | `/local_path` | **WORLD** | 另录 `/planning/bspline`（原始消息，RViz 画不了，留给离线分析） |
| **实时轨迹** | `/lio/robo/odom`、`/lio/path` | **WORLD** | 实际走过的；另录 `/loc/robo/odom`（MAP 系）可对比 |
| **滑动地图** | `/grid_map/occupancy`、`/grid_map/occupancy_inflate`、`/grid_map/sliding_map_bbox` | WORLD | 灰=原始占据、红=膨胀后、框=滑动窗口范围 |
| 基础 | `/tf`、`/tf_static` | — | **缺了什么都对不上**，MAP 系靠它对齐到 WORLD 系 |
| 附带 | `/self_inflation`、`/goal_3d`、`/goal_point`、`/cmd_vel`、`/motion_enabled`、`/test_event`、`/loc/status` | — | 都很小 |

### ⚠️ 为什么默认 120s 就停：滑动地图是最贵的两朵

真机实测带宽（A2）：

| 话题 | 带宽 |
|---|---|
| `/grid_map/occupancy_inflate` | **40.9 MB/s** |
| `/grid_map/occupancy` | 5.7 MB/s |
| 全量档合计（含点云、深度图） | ≈ 75 MB/s（≈4.5 GB/min） |

**`--tracks` 档 ≈ 47 MB/s（≈2.8 GB/min）**，基本上就是这两个话题的贡献。所以：

- 只录"走过拐角那一小段"就够了，不要全场录；
- 默认 120s 自动停就是防你忘记停把盘写满；
- 想再省：在脚本的 `TRACKS_TOPICS` 里删掉 `/grid_map/occupancy_inflate`（省 87%），
  只留 `occupancy` 也能看出滑动地图的轮廓，只是看不到"膨胀后的安全边界"。

### QoS：必须带，脚本已经带好了

脚本自动用 `--qos-profile-overrides-path ~/bags/qos_overrides.yaml`。**不加的话这两类话题一条都录不到**：

- **保留型（transient_local）**：`/global_path`、`/self_inflation`、`/motion_enabled`、`/loc/map`、`/global_planner/raw_map`
- **best_effort**：`/grid_map/occupancy`、`/grid_map/occupancy_inflate`、`/grid_map/sliding_map_bbox`、`/grid_map/depth_cloud`

> 不想用脚本、想手写命令时，记得同样带上这个参数：
> `ros2 bag record --qos-profile-overrides-path ~/bags/qos_overrides.yaml -o <out> /tf /tf_static ...`

## 4. 回放：两条命令

```bash
# 终端 1：回放 bag
ros2 bag play ~/bags/corner_<时间戳>

# 终端 2：RViz，加载回放专用显示配置
ros2 launch scan_planner rviz.launch.py config:=replay
```

### 需要你手动做的一件事

`replay.rviz` 里**没有配"实时轨迹"的显示项**，加一次即可（之后 RViz 会记住，如果保存了配置）：

- `Add` → `By topic` → **`/lio/path`** → `Path`
- 如果 `/lio/path` 是空的（有的 LIO 不发 path），改用 Odometry 累加：
  `Add` → `By topic` → **`/lio/robo/odom`** → `Odometry`，把 `Keep` 调到 `1000` 以上，它会画出一串历史位姿 = 实际轨迹

### 加完之后的对照表

| 你要看的 | RViz 里的显示项 | 颜色 |
|---|---|---|
| 全局轨迹 | `全局路径 global_path` | 白线 |
| 局部轨迹 | `局部路径 local_path` | 绿线 |
| **实时轨迹** | 你刚加的 `/lio/path`（或 Odometry 拖尾） | 默认 |
| 滑动地图 | `原始占据 occupancy` + `膨胀 occupancy_inflate` | 灰点 / 红点 |
| 滑动窗口范围 | `滑动窗口框` | 框 |
| 机身两圆柱（碰撞模型） | `机身两圆柱 self_inflation` | 浅蓝 |
| 坐标系 | `TF` | 轴 + 名字 |
| 地形/楼梯 | `地形图 raw_map` | 默认开；要更细的原始点云再开 `全局点云 cloud_world`（默认关，很大） |

## 5. ⚠️ 坐标系：最容易看错的地方

真机实测，两套坐标系**不是同一个原点**：

| 坐标系 | 哪些话题在里面 |
|---|---|
| **WORLD** | `/lio/robo/odom`、`/local_path`、`/planning/bspline`、`/grid_map/*` |
| **MAP** | `/loc/robo/odom`、`/global_path` |

两者差 **~4.5 m（含约 90° 旋转）**。所以：

- `replay.rviz` 的 **Fixed Frame 默认是 `map`** —— 这时 `global_path` 位置是对的，
  WORLD 系的东西靠 bag 里的 `/tf`（map→world）变换过来，也能对上（这也是为什么 `/tf` 必须录）；
- **如果画面是空的 / 一切都不对**：把 `Global Options → Fixed Frame` 改成 `world` 再看。

## 6. 可选增强

**要在回放里看到"真的机器狗模型"**：真机上没有 `/robot_description`、也没有 `/joint_states`，
所以默认只有 TF 坐标系 + 两个碰撞圆柱代表机器人。想挂上 A2 模型，回放时另开一个：

```bash
ros2 run robot_state_publisher robot_state_publisher \
  --ros-args -p robot_description:="$(xacro ~/scan_planner_github_ws/install/a2_description/share/a2_description/urdf/a2.urdf)"
```

`a2_description/urdf/a2.urdf` 的根 link 正好是 `base`，和真机 TF 约定一致，会自动挂到 bag 的 `world → base` 上。
然后在 RViz 里加一个 `By topic → /robot_description → RobotModel`。

**要在回放里加载一张静态地图**（不录进 bag）：

```bash
# latched 话题，发一次就挂着，起停顺序无所谓
ros2 run map_generator map_pub --ros-args \
  -p file_name:=/abs/path/stairs.pcd -p frame_id:=world -p publish_rate:=0.2
```

注意 `frame_id` 要和 bag 里一致；PCD 若是**别的会话**存的，`world` 原点是开机时机器人的位置，
会整体错位 —— 用 `map_offset_x/y/z` 平移补偿。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| RViz 里一片空白 | Fixed Frame 不对：`map` ↔ `world` 换一下 |
| `/global_path`、`/self_inflation` 没录到 | 少了 `--qos-profile-overrides-path`（保留型话题） |
| `/grid_map/*` 没录到 | 同上（它们要 best_effort） |
| `/planning/bspline` 被静默丢掉 | 录包终端没 source `~/scan_planner_github_ws` |
| `/lio/path` 回放时是空的 | 该 LIO 不发 path → 用 Odometry + `Keep` 替代 |
| 磁盘被写满 | `--tracks` 默认 120s 自动停；或删掉 `occupancy_inflate` |
| `config:=replay` 报"找不到显示配置" | 当前代码分支不是 `chore/record-tools` |

## 8. 数据落在哪

```
~/bags/
├── corner_<时间戳>/            ← 本次的包
│   ├── corner_..._0.db3        ← 数据本体
│   ├── metadata.yaml           ← rosbag2 读它
│   ├── bag_info.txt  meta.yaml ← 可读摘要 / 标签·时长·话题数
│   └── logs_maploc/            ← super_lio 日志（自动收拢）
├── INDEX.md                    ← 录制索引（每次追加一行）
└── qos_overrides.yaml          ← QoS 覆盖（录制时自动使用）
```

录完想量化指标（轨迹误差、速度差、卡住段），用《真机录制与分析手册.md》里的
`analyze_run.py` —— 注意它需要 `/planning/bspline` 等话题，`--tracks` 档已经含了。
